## 本轮补充

- 在 Apple Silicon macOS 27.0.1 上以 Python 3.12 / Tk 9 重跑本地 24 套源码回归入口，全部正常退出。Windows 专属功能和需要 Windows junction 的用例按条件跳过。Windows 的发布通过状态来自独立 CI。
- 修正纳入目录冲突用例的恒真断言。现在预先占用 `dshV3`，检查实际登记到 `dshV3-2`、入口存在且原目录不被写入。临时注入忽略重名的实现，两个新断言均失败。[纳入回归](../scripts/test-install-ops.py)
- 原生窗口测试走生产界面消息队列，增加重复提交与进度窗关闭协议。安装失败覆盖超时、npm 报错和缺少入口三种情况，并检查部分写入清理与配置字节保持一致。[窗口回归](../scripts/test-macos-install-gui.py) · [安装失败回归](../scripts/test-macos-platform.py)
- 在本机使用重新解压的公开 arm64 ZIP，从隔离配置安装并运行 `rc.5`。新增的卸载验收从真实运行的槽开始，经打包 CLI 停机，再使用共享卸载实现核对数据备份、原槽移除、端口释放和配置中未知字段保留。[打包生命周期回归](../scripts/test-macos-app.py)
- 复查两份公开 ZIP。每种架构识别出 7 个 Mach-O 文件，全部带有可读取的部署版本信息。
- 单独启动了正式包的隔离 GUI 副本。副本使用独立的应用标识以免操作日常实例。界面控制工具只取得主窗，未能可靠触发和验证完整的安装对话框流程。GUI 点击安装、后台切换、完成弹窗和卸载仍是待补的成品级流程。

## 本机复测发现的缓存问题

在本机用已有 npm 缓存复测 `rc.1` 时，依赖解析返回 `ETARGET`。同一个依赖通过 npm 的优先缓存模式查询时返回找不到版本，改用在线优先查询后找到了 `0.2.2-rc.1`。再使用优先缓存查询也能找到。只刷新这一个依赖后重试安装，另一个依赖出现了相同的版本查找失败。随后用隔离安装目录和在线优先模式重新解析整棵依赖树，原安装流程重跑通过，包含认证、启停和新的卸载备份检查。发布 CI 的隔离环境通过了 `rc.1`，需另外覆盖旧缓存与在线仓库元数据不一致的安装场景。本轮只更新了测试及说明，发布版的缓存策略仍需处理。

优先补测旧缓存下的安装重试、成品 GUI 的安装和卸载联动，以及 Windows 上两套旧安装的真实纳入与分别启动。macOS 13.5 和物理双屏需要相应的测试环境。

### 日志复验

- 公开包实测把正常零槽标为「注意」，将包内 Node 再报告为 PATH Node，自检摘要还指向 Windows 风格的源码命令。待发布源码把零槽标为正常、去重 Node 来源并指向实际生成的完整报告。
- 正常下载进度删除了触发警告色的「请勿」措辞。全部安装成功时记录成功条数，混合结果保留失败条数和原因。卸载时只将目标槽标为「正在卸载」，防止短暂过期的监听快照被报告成外部实例。上述成功路径在 `rc.5` 的原生 Tk 全链路复跑中通过。
- 真实 npm 超时、404 与旧缓存 `ETARGET` 继续属于诊断信息。公开包的旧缓存风险仍在，原发布 ZIP 保持原样。
