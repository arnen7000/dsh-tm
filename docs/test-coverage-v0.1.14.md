# DSH-TM v0.1.14 验收记录

本版本把零槽启动和设置中的环境检查移到后台。完整报告保存在配置目录下的 `temp/env-check.out`。后台检查结束后，Tk 主线程更新日志并显示手动请求的结果。

| 用户场景 | 验收证据 |
| --- | --- |
| 首次使用，启动检查还在运行 | 在 Apple Silicon、macOS 27.0.1、Python 3.12.15 和 Tk 9 上，用隔离配置和延迟两秒的 Node 版本探测实测窗口事件循环。原生 Tk 在 2.49 秒内处理了 48 次定时回调，启动请求和两次手动请求共用一个检查子进程。 |
| 已有槽，从设置查看自检 | 回归覆盖后台检查完成后显示一次手动请求结果。实测生成的完整报告与同一配置下直接运行命令行自检的输出逐字节一致。 |
| 检查写入失败，需要保留报告 | 回归模拟子进程写入中断，检查错误提示、上一次报告内容和临时文件清理。 |
| 同一浏览器会话操作两个槽 | 用同一 HTTP cookie 容器依次认证真实 dsh `rc.1` 和 `rc.5`，随后用各自的无 token 地址访问，两个槽均返回 HTTP 200。测试覆盖会话行为，浏览器画面未实测。 |

窗口响应测试执行原生 Tk 和真实子进程。Node 探测使用延迟夹具，结果对话框用回调观测。macOS 13.5、实体 Intel Mac、物理双屏和普通 Windows 10 / 11 桌面属于待补的实机覆盖。发布页单列 macOS 15 双架构与 Windows 托管 runner 的测试结果。[v0.1.13 验收记录](test-coverage-v0.1.13.md)

本机通过 24 套源代码回归。解包 arm64 发布候选后，使用独立目录和配置启动实际应用。零槽启动生成一份完整的后台报告，测试未发现自动体检失败日志或残留临时文件。同一候选包还通过了真实 dsh `rc.1` 的安装、认证、启停、备份和卸载验证。
