# dsh 多版本管理器 · 功能说明书

> 对应当前仓库（GUI：`dsh_manager.pyw`，槽上限 6 个）。
> 读者对象：拿到本管理器 + dsh 版本包的人，照本文即可直接管理本机多个互相隔离的 dsh 实例。

---

## 1. 它解决什么问题

dsh（DeepSeek Harness）官方一份安装对应一个版本、一个数据目录、一个端口。当你需要在同一台电脑上
**同时跑多个 dsh 版本**（比如 0.1.5-rc.2 / 0.1.6-alpha.2 / 0.1.7-rc.1），官方装法会互相踩：
端口冲突、数据目录串台、升级即覆盖旧版。

本管理器把每个 dsh 版本装进**各自独立的目录**，用一份 `config.json` 描述三套隔离环境，提供图形界面统一启停、
装/卸版本、纳入已有安装、生成启动器、查端口冲突。每个版本拥有**独立进程 / 独立端口 / 独立数据目录 / 独立 node 运行时 / 独立临时目录**，
互不污染。

### 隔离三轴（核心设计）

| 隔离维度 | 配置字段 | 说明 |
|---|---|---|
| 进程隔离 | 各自 `node.exe` 启动独立进程 | 互不影响，可同时运行 |
| 端口隔离 | `port`（按槽序 4080 / 5080 / 7080 / 9080 / 6081，**避开 6080/8080**，撞车自动顺延） | web 监听不同端口，浏览器按 `host:port` 区分 |
| 数据隔离 | `dsh_home`（`.dsh-home`） | 会话、配置、凭证各版本独立，cookie 绑定 `host:port` 不串台 |
| 运行时隔离 | `node_exe`（版本目录内 `node/`） | 每个版本自带 node，升级/换版不动别的版本 |
| 临时隔离 | `temp_dir` | 各版本临时目录独立；2026-10-31 起统一集中在 `<槽根>/dsh-temp/<槽名>`（设置 → 目录可改） |

## 2. 分发包目录结构

把下面**两份**文件夹放到目标机**相同主目录位置**即开箱即用（无需安装 node / Python）：

```
C:\Users\<你的用户名>\
├─ dsh-versions\                ← 版本包（随本机主目录走，用 <base> 占位）
│  ├─ dshV1\                    ← 版本1（如 0.1.5-rc.2）
│  │  ├─ node\node.exe          ← 自带 node 运行时（隔离关键）
│  │  ├─ node_modules\...        ← dsh 主包及依赖（web + CLI 同包）
│  │  ├─ .dsh-home\             ← 本版本数据目录（会话/配置/凭证）
│  │  ├─ dsh.bat                ← 生成的 web 启动器
│  │  ├─ dsh-cli.bat            ← 生成的 CLI 启动器
│  │  └─ kill-4080.bat          ← 生成的精准停止器
│  ├─ dshV2\  (同构，端口 5080)
│  └─ dshV3\  (同构，端口 7080)
│
<管理器目录>\               ← 管理器（与版本包分开，路径随意）
├─ dsh_manager.pyw            ← 主程序（双击运行，用自带 Python）
├─ dsh_kill.py                ← 端口/进程精准清理模块
├─ config.json                ← 各版本槽的环境定义（权威配置，最多 6 槽）
├─ config\config.example.json ← 配置模板
├─ runtime\python\            ← 管理器自带的便携 Python（无需装 Python）
├─ assets\dsh-icon-violet.ico ← 管理器/快捷方式图标
├─ build_lnk.py               ← 生成桌面快捷方式
└─ docs\                       ← 本文档等
```

> 说明：临时目录由 config 顶层 `temp_root` 统一决定，缺省 = `<槽根>/dsh-temp`
> （缺省 `<home>\dsh-versions\dsh-temp`），每槽一个子文件夹。
> **改它不用手改 config** —— 标题栏「设置 → 目录」里改，会自动建目录、改 `temp_dir`、重写三件 bat。
> 旧版本（2026-10-31 之前）的规则是「有 D 盘就放 `<临时目录根>\dshVx`」，已废弃：
> 那条规则让「槽在 C 盘、临时文件在 D 盘」这层关系在界面上完全不可见。

## 3. 配置说明（config.json）

所有路径用占位符，随目标机用户名自动展开，**不写死盘符/用户名**：

| 占位符 | 展开为 |
|---|---|
| `<base>` | 用户主目录（`C:\Users\<用户名>`） |
| `<home>` | 同 `<base>` |

字段含义：

```jsonc
{
  "install_base": "<home>",          // 版本根：槽装在哪（设置 → 目录可改）
  // temp_root 已废弃：临时文件固定放在各槽的 .tmp 下
  "icon": "assets/dsh-icon-violet.ico",
  "versions": {
    "v1": {                          // 槽位键（v1/v2/v3，内部用）
      "label": "dshV1",             // 界面显示的槽名
      "node_exe": "<base>/dsh-versions/dshV1/node/node.exe",
      "bin_js":   "<base>/dsh-versions/dshV1/node_modules/@deepseek-ai/dsh/lib/bin.js",
      "dsh_home": "<base>/dsh-versions/dshV1/.dsh-home",
      "temp_dir": "<base>/dsh-versions/dsh-temp/dshV1",  // 临时目录（由 temp_root 推出，别手改）
      "port": 4080,
      "browser": "default",          // 打开用哪个浏览器（default=系统默认；也可 chrome/edge/firefox/任意 exe；设置里有下拉）
      "extra_args": ["web","--host","127.0.0.1","--port","4080","--no-open"]
    }
    // v2 / v3 同构，端口 5080 / 7080
  }
}
```

改版本号/路径/端口只动这个文件，管理器代码不写死任何值；**浏览器和目录都有界面了**
（标题栏「设置」→ 浏览器下拉 / 目录两行），不用手改。

## 4. 主界面功能

每个版本一张卡片，顶部显示「≡ 槽名 · 真实版本号」（如 `≡ dshV2 · 0.2.1-alpha.2`；
端口不在这里，下面状态行有），**居中在标题行的正中间**（2026-10-31 起；`labelanchor="n"`），
下面是操作区。

状态行末尾的 `⚠N` 是体检徽标（N = 该槽的错误 + 警告条数）。**鼠标停在状态行上**会弹一个
深色提示框，逐条列出是哪几个问题 —— 光看数字猜不出来，翻日志又太远。
想看全部点底部「槽体检」（只读，不提供任何修复按钮）。

### 4.1 卡片内按钮

| 按钮 | 功能 |
|---|---|
| **启动**（绿） | 用本槽配置启动 dsh web（自带 node + 注入 DSH_HOME/TEMP）。启动前先做端口预检（见 §5） |
| **停止**（红） | 委托 `dsh_kill.py` 按「进程签名 + 本槽端口」精准停止，**只杀本版本**，不误伤别的 dsh |
| **打开 Chrome/Edge** | 按 `config.browser` 打开 `http://127.0.0.1:<port>`，自动带登录 token |
| **复制入口 URL** | 复制 `http://127.0.0.1:<port>?token=...` 到剪贴板；落盘 token 就地等长掩码，不泄露 |
| **程序目录** | 资源管理器打开本版本安装目录（bin_js 所在） |
| **数据目录** | 资源管理器打开本版本 `.dsh-home` 数据目录 |

### 4.1b 标题栏：设置（2026-10-31 新增）

| 项 | 说明 |
|---|---|
| **显示哪几个槽** | 列表里双击（或按空格）切换 `[✓]` / `[  ]`。**至少留一个** |
| **左右顺序** | ① **直接在主窗口拖卡片**（推荐，手机手感）：按住卡片**任意位置**往外拖 —— 卡片浮起、其它卡片让位，松手落下即生效（拖过按钮也不会误触发按钮）；② 设置里选中一行 → 「上移 ↑ / 下移 ↓」；③ 设置里直接**拖列表中的行** |
| **最多显示几个** | 底部 `Spinbox`（1..`MAX_SLOTS`）。勾选数超过它时只显示靠前的几个，保存后会提示 |
| **每个槽用哪个浏览器** | 选中列表某行 → 下拉选 默认浏览器 / Chrome / Edge / Firefox / 选择其他程序…（任意 exe）。没装的标「（未安装）」。写进该槽的 `browser` 字段，卡片按钮立刻变成「打开 Chrome」这种 |
| **安装根目录**（2026-10-31 新增） | 版本装在哪，写 config 顶层 `install_base`。**首次安装/纳入前会专门问一次**（默认当前安装根，缺省 `<home>` 即 C 盘），确定后**锁定只读** —— 这里只显示、不能改。理由见下 |
| **临时目录**（2026-11-02 变更） | **不再单独配置**：新装/新纳入的槽，TEMP 固定为 `<槽目录>/.tmp`。已装的旧槽保持原路径不动。 |

- **安装根为什么锁死**：一次装到两个地方，管理器就得同时管两处 —— 卸载备份目录、
  空壳扫描、新建槽的落点全部要按「多根」重写。与其做一个半成品多根管理，不如把位置锁在第一次：
  **装之前问一次代价最小，装完再问就变成搬家**。
  要换位置只有一条路：把所有版本卸载干净（卸载会先备份用户数据）→ 重新安装，那时会重新问。
  第二道闸在 `_apply_dir_settings`：即便有人绕过界面改了这个值，有槽时也会被拒绝写入。
- 「安装根目录」和「临时目录根」**不能一次同时改**：会算出「基于新安装根、但槽还没搬过去」的临时路径，等于把 TEMP 指到一片空地。分两步走。
- 零槽（还没装任何版本）时安装根**仍可编辑** —— 那时改了没有任何东西会断链，也正好是装第一个版本之前。

- 保存写进 `config.json` 顶层 `ui` 段（`max_visible` / `order` / `visible`），**立即生效不用重启**。
- **隐藏 != 卸载**：卡片不画，但进程、端口、数据目录、「卸载」「杀全部」的名单一概照旧。
- 隐藏后窗口宽度跟着变窄；全隐藏会被拦住（空白界面容易被当成程序坏了）。
- 新装的槽自动出现在末尾（`order` 是旧快照，代码会把没记过的槽接在后面）。
- 纯逻辑在 `dsh_ui_prefs.py`（`move_to` / `merge_display_order` 也是纯函数），回归 `scripts/test-ui-prefs.py`。
- 拖拽排序只重排**显示中**的那几张卡片；隐藏的槽在完整顺序里原地不动，以后重新显示时位置不会跑。拖回原位不会写盘。

### 4.2 状态显示

卡片实时反映：运行中（本管理器启动 / 外部或上一会话启动）/ 启动中 / 已停止 / **端口被非 dsh 进程占用**（红色告警）。

### 4.3 底部操作区

| 按钮 | 功能 |
|---|---|
| **杀全部进程**（红） | 精准清理所有本机 dsh 进程（按 node + `@deepseek-ai/dsh` 签名判定，不杀无关 node） |
| **生成启动/kill/CLI bat** | 把每个在管槽的 `dsh.bat` / `kill-*.bat` / `dsh-cli.bat` 一次性重新生成（见 §6） |

### 4.4 安装 / 卸载（第三行）

| 按钮 | 功能 |
|---|---|
| **安装官方版 dsh** | 装到**下一个空槽**。对话框会列出 npm registry 上**全部已发布版本**（标注「最新 / 预览 / 已弃用」），点一行即填；也可手填版本号或 `latest` / `next` 这类 dist-tag。默认选中 dist-tag `latest`。列表拉不到时（断网/代理）仍可手动输入 |
| **扫描已装 dsh 并纳入** | **全量重扫**本机管理范围外的 dsh（npm 全局 / 版本目录里的孤儿），弹**勾选列表**：每项先体检（版本号、`lib/bin.js`、依赖完整性、旧数据目录），不完整的灰掉不可选；没勾的记进 `adopt_ignored`，以后启动不再提示（见 §7.2） |
| **卸载 / 移出…**（红） | **一次一个**（单选）。破坏性动作，多选容易连带勾错只差一个后缀的槽。流程见 §7.1 |

> 关闭管理器窗口时，默认**保留运行中的 dsh**（它继续在后台提供服务），不会跟着关掉。

## 5. 端口冲突预检（启动前）

点「启动」或双击 `dsh.bat` 时，先用 `dsh_kill.py --precheck-start` 查本槽端口：

- **被非 dsh 程序占用**（如别的软件、被以前误装的 dsh）：明确弹窗「XX 软件占用了端口 NNNN，请处理」，
  写日志，**拒绝启动**——绝不自动结束别人的程序，交给用户手动处理。
- **被你自己的另一个 dsh 占用**：提示「端口被你的 dsh 占用」，询问是否先清理再启动。
- 预检脚本缺失：仅警告并直接启动（不阻断）。

日志统一前缀 `[bat-precheck][槽名]` / `[启动失败：端口被非 dsh 程序占用]`，便于排障。

## 6. 启动器 bat 生成（web + CLI + kill）

点「生成启动/kill/CLI bat」后，每版本目录生成 3 个 bat，环境隔离完全一致：

| 文件 | 作用 |
|---|---|
| `dsh.bat` | web 启动器：设 `DSH_HOME`/`TEMP`/`TMP`、把自带 `node` 前置 `PATH`、端口预检、再 `node bin.js web --host 127.0.0.1 --port NNNN --no-open %*`（CLI 参数透传） |
| `kill-NNNN.bat` | 精准停止本槽：只查本槽端口占用者，按签名清理，不杀别的版本 |
| `dsh-cli.bat` | **CLI 启动器**：与 web 同环境隔离（各自 node / `.dsh-home` / 临时目录），`node bin.js %*`，把参数透传给 dsh CLI 模式。**注意：dsh CLI 必须显式指定 `--profile <name>`**（可用 profile 见该槽 `.dsh-home\profiles\`，常见的是 `headless` / `web`）；不带参数运行只会得到 `error: --profile <name> is required`，并不是交互式 REPL |

**关键事实**：dsh 的 web 与 CLI 是**同一个 npm 包**（`@deepseek-ai/dsh`，`bin: dsh → lib/bin.js`），
没有独立 CLI 包。所以「CLI 跟随 web 一起更新、放进各自安装包、各版本隔离」= 每个版本目录都有
隔离的 `dsh-cli.bat`，点一次按钮 web/CLI 的 bat 同步重生，永不脱节。

> 历史坑已修：2026-10-01 加端口预检后，`dsh.bat` 生成因 `%PRECHK_PY%` 含字面量 `%` 被 Python 当格式符
> 导致崩溃，已转义为 `%%PRECHK_PY%%` 修复。

## 7. 卸载与纳入

> 2026-10-30 起「换版本」功能已整体移除（按钮、对话框、`scripts/switch-version.ps1` 一并删除）。
> 想换版本 = **卸载该槽 + 用「安装官方版」装一个新槽**（数据目录会先备份，可迁回）。

### 7.1 卸载某个 / 某几个槽

底部「卸载 / 移出…」→ 选中要卸的槽（**一次一个**）→ 二次确认 → 后台执行：

| 步骤 | 说明 |
|---|---|
| 1. 停进程 | 走 `dsh_kill` 的「签名 + 端口」门控：**只杀本槽的 dsh**；端口若被别的程序占着，拒绝杀（卸载不该顺手结束别人的软件） |
| 2. 备份 | 落到 `<install_base>\dsh备份\<槽>-userdata-<时间戳>\`：`.dsh-home` **全部内容**（会话/设置/凭据/插件配置）+ `_slot-package.json` / `_slot-package-lock.json`（**装过哪些插件、钉的版本**）+ `_meta.json`（槽名 / **实装版本号** / 端口 / 目录 / 时间 / `config.json` 原片段）。**备份失败就中止该槽**（不删文件、不从配置移除） |
| 3. 删整个槽目录 | 备份成功后，`node_modules` / `node` / `*.bat` / `.dsh-home` / `.tmp` **全删**，最后 `rmdir` 槽根。为什么不再"保留用户数据"：留着空壳目录会让下次装同一槽被命名成 `dshV1-2`（`unique_dir` 判重），看着像没卸干净 |
| 4. 改配置 | 从 `config.json` 移除该槽（改前自动 `.bak-<时间戳>`）；**只有文件清理干净的槽才会被移除**，否则保留在配置里可重试 |

安全边界（与 `scripts/uninstall.ps1` 的 `Test-SafeToDelete` 同一套规则）：
只删「严格位于槽根目录之内」的条目；槽根本身、用户主目录、管理器目录、盘符根一律拒绝；
`bin_js` 落在 npm 全局 `node_modules` 下的槽**不能按槽删**（那是所有全局包共用的目录，
只能 `npm uninstall -g`）。槽**外**的临时目录（`<临时目录根>\<槽>`）不属于槽，不动它。

卸载完成后管理器自动重启以反映新的槽列表；全部卸完会回到「零槽引导卡」。

### 7.2 纳入本机已有的 dsh（首次启动 / 手动扫描）

管理器启动后会扫一遍「管理范围外」的 dsh（npm 全局、版本目录里的孤儿），
弹**勾选列表**（不是"是/否"一刀切，多个版本可分别选）。

每一项先**体检**，结果显示在行里：

| 体检项 | 判据 | 不过会怎样 |
|---|---|---|
| 版本号 | 读 `@deepseek-ai/dsh/package.json`（不信 `label`） | 读不到 → 拒绝纳入 |
| 入口 | `lib/bin.js` 存在 | 缺 → 拒绝（纳入后必然启动失败） |
| 清单 | 包内 `package.json` 可读、`version` 形态合法 | 缺/坏 → 拒绝 |
| 依赖 | `package.json` 声明的依赖在 `node_modules` 里都能找到（最多点名 5 个） | 缺 → 拒绝（半装） |
| 空壳 | `lib/` 里至少有一个 `.js` | 空 → 拒绝 |
| 旧数据 | `<安装目录>/.dsh-home`；**仅** npm 全局安装才回退看 `~/.dsh` | 没有 → 提示"纳入后是干净新槽" |

体检不通过的项**勾选框是灰的**并写明原因。

纳入执行（任一步失败即中止，原安装一个字节都不动）：

1. 备份原用户数据目录到 `<install_base>\dsh备份\<槽>-userdata-<时间戳>` —— **失败就中止**
2. 复制 `node_modules` + 复制一份自带 node 运行时（与既有槽同构）
3. **校验复制结果**：版本号必须与体检时一致、`bin.js` 必须在；不一致就清掉半成品
4. 把第 1 步的备份**复制**进新槽 `.dsh-home`（会话/凭据跟过来，原目录没动）
5. 写 `config.json`（`<base>` 占位符、`label` 用固定槽名 `dshVx`、`temp_dir` 走统一规则）
6. 生成三件 bat，再对一遍"槽的形状"（自带 node / 入口 / 数据目录 / 临时目录 / bat）

**不再提示的机制**：没勾的项写进 `config.json` 的 `adopt_ignored`，以后启动静默跳过；
点「扫描已装 dsh 并纳入」是**全量重扫**（连之前跳过的也重新列出），勾上就会从名单里删掉。
已纳入的安装因为落在版本根之内，本来就不会被再次扫出来。

## 8. 临时目录与磁盘空间

**落点**（2026-10-31 起统一）：`<temp_root>/<槽目录名>`，`temp_root` 缺省 = `<槽根>/dsh-temp`。
缺省就是 `<home>\dsh-versions\dsh-temp\dshV1..V4` —— 临时文件**跟着安装根走**，
换盘 / 换 `install_base` 时一起搬，不用改两处。

- 改法：标题栏「设置 → 临时目录根」。保存后自动建目录、改 `temp_dir`、重写三件 bat。
- 手改 config 也可以（顶层 `temp_root`），但改完要自己点「生成启动/kill/CLI bat」，
  否则 `dsh.bat` 里的 `set "TEMP=..."` 还是旧路径 —— **槽体检会报这条不一致**（只报不修）。
- 老规则（2026-10-31 之前）：有 D 盘就放 `<临时目录根>\dshVx`，否则槽内 `.tmp`。
  已废弃 —— 旧规则会让槽在 C 盘、TEMP 却在 D 盘，界面上看不出两者的关系；
  现在 TEMP 一律跟着安装根走。

**能删吗**：能。里面全是 dsh / Chrome 运行期的**一次性 scratch**（`dsh-acl-skill-XXXX`、
`dsh-spill-XXXX`、`scoped_dir*`、`chromecrx_chrome_Unpacker_*`），进程退出即孤儿，
删了下次启动只会新建全新的，**不影响会话**。会话/配置/凭据始终在 `.dsh-home`。

**为什么会有残留**：这些目录由 dsh 自己建，正常退出时它会 `rm` 掉；被强杀
（任务管理器结束进程 / 「杀全部进程」/ 崩溃）时清理不执行 → 残留。**残留条数≈强杀次数**。
槽体检在累积超过 20 项时会提示（只报不修）。

**C 盘空间**：真正吃盘的是槽本身（`node_modules`，每槽 0.7–1.3 GB），临时目录通常只有几百 KB
到几 MB。要省 C 盘请改「安装根目录」，不是改临时目录。

## 9. 首次部署（给拿到包的人）

1. 把 `dsh-versions` 放到 `<你想要的安装根>\dsh-versions`；管理器目录本身放到任意位置。
2. 双击 `<管理器目录>\dsh_manager.pyw` 启动管理器（用自带便携 Python，无需装 Python）。
3. 或运行 `python scripts\check-env.py` 做完整性自检，`python build_lnk.py` 生成桌面快捷方式。
4. 在管理器里点各版本「启动」，浏览器自动打开对应 `http://127.0.0.1:<port>`。
5. 需要命令行 CLI：到版本目录运行 `dsh-cli.bat --profile headless`（`headless` 可换成该槽 `.dsh-home\profiles\` 下已有的名字，常见为 `headless` / `web`）。**不要直接双击**——dsh CLI 需要 `--profile`，无参数运行只会报错退出。

需要桌面快捷方式：运行 `scripts\build_lnk.py`（图标用自带 `assets/dsh-icon-violet.ico`）。

## 10. 日志与排障

- 管理器所有操作写决策日志（启动/停止/端口冲突/安装/纳入/卸载），含端口、PID、占用者识别。
- 端口被非 dsh 占用：看弹窗 + 日志里的「XX 软件占用了端口 NNNN」，去任务管理器结束对应程序再启动。
- 启动卡死：检查 `dsh_kill.py` 自检脚本是否齐全；管理器会自动清理 v2 的 `.credentials.yaml.lock` 死锁。
- 换机后路径不对：确认 `config.json` 用的是 `<base>` 占位符而非写死盘符；重跑「生成启动/kill/CLI bat」即可重生正确路径。
