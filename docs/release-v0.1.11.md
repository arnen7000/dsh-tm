# DSH-TM v0.1.11 交付与验收

## 核心范围

从 GitHub 的 Windows v0.1.10 基线增加原生 macOS 支持。Windows x64、Apple Silicon 和 Intel Mac 共用六槽界面、配置诊断和 CLI JSON v1。核心流程包括安装和纳入、启停和浏览器访问、体检、移出和接回、卸载和搬迁。macOS 额外交付独立的槽位 `.command` 入口。

## 设计决策

- 以 GitHub 的六槽实现为准，复用本机旧项目的 macOS 经验。Mac 版在应用支持目录读取配置，Windows 继续使用便携目录，保留 BOM 和未知配置字段。
- 按槽内程序入口、监听端口和进程创建时间核实进程归属。关闭管理器后运行中的槽继续服务。认证链接保留在当前运行的管理器内存，输出写盘前脱敏。
- 数据操作先核实停机和备份，按边界处理符号链接及 Windows junction。搬迁在校验通过后提交配置。macOS 后台操作通过主线程队列刷新界面，避免配置已提交时进度窗仍锁住操作。
- 用 GitHub Release 分发三个独立的 ZIP。Mac 包使用临时签名，Apple Developer ID 签名、公证及 App Store 发布延后。Mac 预发布用户可按同一配置目录升级到本版。

## 自测与发布条件

| 检查 | 覆盖内容 |
| --- | --- |
| Windows 总检与便携包 | 配置、编码、扫描和纳入、槽位操作、解压后 Python/Tk、Node、npm 和 CLI。 |
| 两种原生 macOS | macOS 15 上构建、校验和解压，验证二进制架构、13.5 最低部署版本、临时签名、启动和正常退出。 |
| 实际 dsh 生命周期 | 两种 Mac 架构用内置运行时从空配置安装 `@deepseek-ai/dsh@0.2.2-rc.1`，访问未认证和认证页面并验证日志脱敏、批量启停和端口释放。 |
| 进程与数据安全 | 六槽并行、外来 Node、不同槽进程、PID 复用、进程信息受限、备份损坏、路径越界和搬迁失败回滚。 |
| 本机试用回归 | 设置窗贴边、随主窗移动和增高、松手吸附、Tk 9 触控板滚动；空槽及带数据槽的卸载、备份核验和移出管理；认证链接不可用时提示恢复方法。 |

macOS 13.5 是经包内二进制检查的部署目标。双架构生命周期在 macOS 15 运行，本机还使用 Apple Silicon macOS 27.0.1 验证 App。Windows 便携包在 GitHub 的 Windows Server 2025 x64 runner 验证。

额外定位回归覆盖主屏左侧及右侧的外接屏坐标，真实窗口交互在本机单屏验证。系统发出终止信号时，正在等待确认的模态窗口可能需要先关闭，该边界和正常关窗分开验证。

正式发布使用 `main` 上同一提交生成的三个包。GitHub Actions 的发布步骤等待三平台完成后校对每份 ZIP 的 SHA-256，再公开发布和校验文件。实际运行记录和产物清单随 [GitHub Release](https://github.com/arnen7000/dsh-tm/releases/tag/v0.1.11) 提供。

## 用户验收

从发布页下载对应架构的 ZIP。Mac 按[首次打开说明](macos.md)启动，Windows 解压后双击 `start-manager.bat`。保留原来的槽数据，先确认现有槽显示正确，再用一个独立试用槽走安装、启动、浏览器访问、停止和卸载流程。
