# dsh 版本管理器 · 使用说明

> **界面入口变更（2026-11-01 起，2026-11-11 复核）**：主界面只保留槽卡片、日志与「全部启动 / 全部停止」；「安装官方版 dsh」「扫描已装 dsh 并纳入」「卸载 / 移出管理」在「设置 → 版本管理」，「槽体检 / 生成 bat / 检查运行环境」在「设置 → 维护」。下文若出现「底部按钮」「杀全部进程」「设置 → 临时目录根」等字样，均为旧版界面记录，一律以 [README](../README.md) 第 4 章为准。
> 本文是**管理器本身的操作手册**：界面每个按钮做什么、日志怎么看、`config.json` 每个字段什么意思。
>
> 安装方式、全场景流程、注意事项请看仓库根目录的 [`README.md`](../README.md)；想改代码看 [`架构与维护说明.md`](架构与维护说明.md)。

## 1. 它管的是什么

一个 Windows 小工具，让同一台电脑上**并存 1~6 个互相隔离的 DeepSeek Harness（dsh）版本**，用图形界面统一管理。

**每一槽都是完整的本地隔离安装**：

```
<安装根>\dsh-versions\dshV1\
    node\                 ← 该槽自带的 node 运行时
    node_modules\         ← 该槽自己的依赖树（含 @deepseek-ai/dsh）
    .dsh-home\            ← 该槽的数据目录（会话 / 配置 / 凭据 / 插件配置）
    dsh.bat               ← 起 web 服务
    dsh-cli.bat           ← 命令行模式
    kill-<端口>.bat       ← 停掉本槽
```

五个版本 = 五套这样的目录，互不共享任何东西：

| 隔离轴 | 分开什么 |
|---|---|
| 进程 | 各跑各的 node，内存不共享 |
| 数据 | 各自的 `.dsh-home`，会话与凭据不串台 |
| 端口 | 按槽序取 4080 / 5080 / 6080 / 7080 / 8080（不特意避开 6080/8080），先查 config 再真实 bind 探测，撞了就近顺延 |
| 运行时 | 每槽自带 node，`node-pty` 这类原生模块的 ABI 不会错配 |
| 临时目录 | 各自的 `temp_dir`，缺省跟着安装根走 |

> 槽名固定是 `dshV1` / `dshV2` / …，**不随版本号变**。真实版本号单独显示在卡片标题右边（管理器读该槽 `package.json`，不是手填的）。
>
> 具体装哪个版本由 `config.json` 决定，管理器与版本无关。

## 2. 系统要求

| 需要 | 要求 | 用在哪 |
|---|---|---|
| **Windows** | 10 / 11（x64） | 全部：`ctypes` 调 Win32、`netstat` / `tasklist` / `taskkill`、`.lnk` |
| **Python** | ≥ 3.8，**必须带 tkinter** | 管理器 GUI。脚本零第三方库依赖 |
| **Node** | ≥ 22.19（新版 dsh 要 ≥ 24.9） | 管理器**包内自带** `runtime\node`，装槽时拷进新槽。**你不用自己装** |
| **浏览器** | 任选一个已有的 | 打开 dsh 网页版。**不自动安装任何浏览器** |

**不会打扰你机器上的其它软件**：不写全局/用户 `PATH`、不改注册表、不动别人的 node 或 npm 全局包；只在自己的子进程里注入 `DSH_HOME` 与 `TEMP`。

缺依赖时的表现是**明确报错**，不会静默装坏。想自己查一遍：`python scripts\check-env.py`。

## 3. 安装与首次启动

| 你怎么用 | 做什么 |
|---|---|
| **已经拿到便携包**（自带 python + node） | 解压 → 双击 `start-manager.bat` |
| **从仓库源码起步**（自己装了 python / node） | 同上；`runtime\` 不存在时管理器会用系统 Python / Node |
| **全新机器**（缺 python 等） | 先装 Python（勾 tcl/tk）与 Node ≥ 22.19，再双击 `start-manager.bat` |

`start-manager.bat` **只打开窗口，什么都不装**。它按「包内 pythonw → PATH 的 pythonw → PATH 的 pyw」依次尝试；一个都不行会打印该装什么。

`start-manager-debug.bat` 用**带控制台**的 Python 打开 —— 「双击没反应」时用它，traceback 直接可见。

### 第一次安装时会先问「放在哪」

一个槽都没有时，点「安装官方版 dsh」或「扫描已装 dsh 并纳入」会先弹一个位置确认框：

- 缺省 = 你的用户主目录（`<home>`）；
- 弹框里会预览三处落点：版本目录 / 卸载备份 / 临时文件；
- **确定后锁定**（不能直接手填新路径）。但**换盘 / 换位置不用卸载** —— 用「设置 → 目录 → 移动安装根目录…」整体搬；
  只有想换到「一个全新的空位置」时，才需要先把槽全部移出 / 卸载，锁才会解开。

理由：一次装到两个地方，管理器就得同时管两处 —— 备份目录、临时目录、空壳扫描、新槽落点全要按"多根"重写。与其做半成品，不如把位置定在第一次。

## 4. 界面

### 4.1 卡片

每个版本一张卡片，标题 `≡ dshV1 · 0.1.5-rc.2`（`≡` 是拖拽手柄的视觉提示；右边是该槽**真实装的**版本）。

状态行每 1.5 秒刷新：`运行中 pid=xxxx ✓` / `启动中…` / `外部占用 :端口` / `已停止 :端口`。末尾出现 `⚠N` 表示体检发现 N 个问题 —— **鼠标停在状态行上**会弹出提示直接列出是哪几条。

| 按钮 | 作用 |
|---|---|
| **启动** | 拉起该槽的 `node bin.js` + 该槽 `extra_args`，注入独立 `DSH_HOME` / `TEMP`。启动前做端口预检、清理本槽 `.credentials.yaml.lock` 死锁 |
| **停止** | 按「该槽签名 + 端口」精准清理，**不误杀其它 node** |
| **打开 Chrome / Edge / Firefox / 浏览器** | 用该槽配置的浏览器打开，自动带完整入口 URL（含 token）。最后那个 = 系统默认浏览器 |
| **复制入口 URL** | 复制带 token 的完整 URL。**日志里的 token 已打码**，取 URL 请用这个按钮 |
| **程序目录 / 数据目录** | 在资源管理器里打开该槽目录 / 它的 `.dsh-home` |

### 4.2 操作入口（旧版为底部按钮，现收进「设置」）

| 按钮 | 作用 |
|---|---|
| **安装官方版 dsh** | 装到下一个空槽。详见 §5.1 |
| **扫描已装 dsh 并纳入** | 把本机已有的 dsh 整理成独立槽。详见 §5.2 |
| **槽体检** | 默认**只报告**：这个槽现在的样子和登记的样子差在哪；要修得你自己点「修复…」。详见 §4.4 |
| **卸载 / 移出管理** | 两个不同的动作，别选错。详见 §6 |
| ~~杀全部进程~~（界面已移除） | 2026-11-01 起改用 CLI：`python dsh-tm.py kill-stray --yes`。仍只认 `@deepseek-ai/dsh` 签名，不碰其它应用的 node |
| **生成启动/kill/CLI bat** | 按当前 `config.json` 重新生成各槽三件 bat（改过 `temp_dir` / 端口后必须点一次） |

### 4.3 标题栏与设置

标题栏只有一枚 **「设置」**，打开一个侧栏窗口，分五组：

| 分组 | 内容 |
|---|---|
| **版本管理** | 「安装官方版 dsh」「扫描已装 dsh 并纳入」「卸载 / 移出管理」。主界面只留槽卡片 + 日志 + 全启停，装/纳入/卸载统一收在这里 |
| **界面** | 「显示哪些槽 / 顺序 / 浏览器…」；**主题**：跟随系统 / 浅色 / 深色 —— 三个分段按钮，**选中的那个是蓝色填充 + 白字**，一眼能看出当前用哪个，切换立即生效并记住；**界面语言**：中文 / English —— **切换立即生效，不需要重启**（管理器会遍历控件树就地重译，卡片状态行会重画一次），配置存在 `config.json` 的 `ui.lang`，缺省 `zh`；英文模式下「使用说明」会自动打开 `docs/user-guide.en.md` |
| **目录** | 安装根目录（有槽后锁定，但可「移动安装根目录…」整体搬家，不用卸载）；下方写明"版本装在哪、临时文件在哪" |
| **维护** | 检查运行环境 / 槽体检 / 生成启动·kill·CLI bat / 使用说明 |
| **日志** | 日志大小与行数、清理入口 |

> 浏览器在「界面 → 显示哪些槽 / 顺序 / 浏览器…」里改：系统默认 / Chrome / Edge / Firefox / 选择其他程序… 。没装的标注「（未安装）」，选它也不报错，会兜底到系统默认。

**隐藏 ≠ 卸载**：界面设置只决定画哪几张卡片。进程跟踪、端口、数据目录、卸载名单永远是全量，改完**立即生效**，不用重启。把全部槽都隐藏了也不会变成空白 —— 会换成一张带「打开设置…」的提示卡。

**拖动排序**：按住卡片任意位置（含按钮）往外拖，卡片浮起来跟着鼠标走，其它卡片实时让位，松手落盘。鼠标移到卡片空白处会变成四向箭头 —— 那就是"这里能拖"的信号。

**只有一个安装根**：各槽的临时文件自动放在 `<槽目录>/.tmp`，不需要单独配置（2026-11-02 起）。
**装完之后想换盘 / 换位置不用卸载** —— 「设置 → 目录 → 移动安装根目录…」会把所有版本连同数据一起搬过去（复制 → 校验 → 改配置 → 删旧位置；搬之前会先算目标盘空间，并要求所有槽先停止）。搬完界面自动切到新位置。

### 4.4 槽体检

点「槽体检」开一个报告窗口，可一键复制结果。它把这个槽"现在的样子"和"登记的样子"逐项对比，分三级：

| 级别 | 含义 | 例子 |
|---|---|---|
| **错误** | 现在起不来 | 缺 `bin.js`、缺 `node`、槽目录没了 |
| **警告** | 能跑，但迟早出事 | 用系统 node、`node-pty` 缺失、端口与 kill bat 不符、两槽抢同一端口、`temp_dir` 与 bat 不一致 |
| **提示** | 只是信息 | 实装版本号、数据目录大小 |

**默认一个字都不改**：槽里少了什么、多了什么，有可能是你故意的（换了 node、给 dsh 打了补丁、把 `.dsh-home` 挪到别处），管理器替你"修好"等于覆盖你的选择。

**要修得自己点**：窗口底部有「修复 + 下拉（只列有错误/警告的槽）+ 修复…」。点了才动，而且**只补、不删、不覆盖**：

| 缺什么 | 点「修复…」的结果 |
|---|---|
| `node/node.exe` | 补：从其它槽或包内 `runtime/node` 复制一份 |
| `.dsh-home` / `.tmp` 目录 | 补：建空目录（原来的会话/凭据不会回来） |
| `lib/bin.js`、依赖、dsh 的 `package.json` | **不补**（那等于重装），会当场说明并建议用「安装官方版 dsh」重装 |

补完会再体检一次；还有补不了的会如实告诉你，不会假报成功。

### 4.5 外部启动的 dsh，管理器怎么看

判据是**端口**（`config.json` 里配的那个），不区分是谁启动的：

| 场景 | 卡片状态 | 点「启动」 | 点「停止」 |
|---|---|---|---|
| 用槽里的 `dsh.bat` 启动（同端口） | 「运行中 pid=xxx ✓」，和自己启动的一样 | 弹框问「是否结束该 dsh 进程并启动新实例？」 | **会把它杀掉** |
| 终端里直接 `node …/bin.js web`（同端口） | 同上 | 同上 | 同上 |
| 启动时改了端口（`--port 9999`） | 「已停止」（管理器只盯配置里的端口） | 会再起一个实例，两个各用各的端口 | 只杀配置端口上的那个 |
| 端口被**别的程序**占了 | 「端口被非 dsh 程序占用」 | 拒绝启动并说明，**不杀那个程序** | 不碰它 |

两点要注意：

- **「停止」会杀掉外部启动的 dsh。** 这是有意的 —— 否则「用 bat 起的 dsh 杀不掉」会变成另一个坑。
- **同端口不同版本**：手动跑 dshV3 却占了 5080（v2 的端口），管理器会把 **v2** 判成运行中，停止时杀的是 v3 那个进程。**手动启动请用该槽自己配的端口。**

> 外部启动的 dsh **不受管理器的 `DSH_HOME` / `TEMP` 注入影响**，用的是你终端里的环境变量。要完全等同，就用槽里由管理器生成的 `dsh.bat`。

## 5. 加槽位

两个按钮都不需要手改 `config.json`：都会自动分配不冲突的端口与目录名，写前备份配置，完成后**界面原地刷新**（不用重启进程）。

### 5.1 安装官方版 dsh

1. 弹窗上半是**版本列表**（实时从 npm registry 拉，标注 最新 / 预览 / 已弃用）；
2. 输入框是**唯一事实来源**：从列表选只是帮你填进去，也可以直接手写；
3. 版本号格式：三段数字 + 可选预发布标记（`0.2.0-rc.2` / `0.1.6-alpha.2`）。常见手误会先问一句再纠正（`v0.2.0-rc.2` → `0.2.0-rc.2`）。

**一次可以装多个**：Ctrl 点选 / Shift 连选，或在输入框里用逗号/空格分隔。上限 = 还有几个空槽，窗口标题会写"一次最多 N 个"。某个失败**不中断队列**，全部结束后统一刷新一次界面。

**槽位分配**：编号与目录名一一对应（`v3` ↔ `dshV3`）。每点一次装到**下一个真正空着的编号** —— 只要 `dshV3` 这个目录还在磁盘上（哪怕已经移出管理），`v3` 就算被占，会直接跳到 `v4`，**不会**再出现 `dshV3-2` 这种名字。零文件的空壳不算占用（装之前会清掉复用）。端口按槽序分配且与现有槽都不同。

**网络失败自动回退**：官方源不通时（`ECONNRESET` / `ETIMEDOUT` / `EAI_AGAIN` 等，**不管退出码是负数还是 1**）改用 `registry.npmmirror.com` 重试一次，**只对本次命令生效**，不改全局 npm 配置。下载阶段本身也调紧了重试（`--fetch-retries=1`），失败会更快暴露，不会白等五分钟。

**装失败会当场收回半成品**，不留零文件残壳，也不会占着槽名导致下次变成 `dshV1-2`。

**安装期间那个进度窗**：这个窗口的标题栏是管理器**自己画的**——标题在左，右上角一个 **「—」**，
没有 X。点「—」就是最小化，安装继续在后台跑，任务栏里点一下就能收回来（标题栏还能拖着走）。
装完会自己弹回来报结果。
**装的时候不用干等**：这个窗口**不挡主界面**——已装好的版本照常能「启动 / 停止 / 打开浏览器」，
一边装一边用别的版本没问题。（「安装官方版」「卸载」「移出」「移动」这些会改磁盘的按钮仍然锁着，
免得装到一半又去动目录。）
（中途关掉会留下半装状态，所以这里干脆不给关闭按钮。）

### 5.2 扫描已装 dsh 并纳入

- 扫当前版本根 + npm 全局 `node_modules`，列出所有 `@deepseek-ai/dsh`；
- 弹**勾选列表**：体检通过的默认勾上、不通过的禁用；不点「纳入勾选的」什么都不动；
- **已经在管的槽不会出现**（判据是磁盘：目录已在 `config.json` 的 `versions` 里就跳过）；
- **移出过的槽会列出来**：勾选后是「原地接回」（不复制文件）；
- 启动时**不扫描**；只有点「扫描已装 dsh 并纳入」才会查磁盘，也不会记录「以后不再提示」的名单。

**纳入有两条路**（按目录位置自动判断，不用你选）：

- **目录就在本管理器的版本根下**（`<安装根>\dsh-versions\` 里，典型是"移出过的槽"）→ **原地接回**：
  只改 `config.json`，**不复制任何文件**，几秒完成；端口从槽里的 bat 读，被别的槽占了就换一个并重写 bat；
- **在别处**（npm 全局、别的安装）→ **复制一份**进版本根，步骤见下。

**复制纳入会做什么**：

1. 把该安装的 `node_modules` **复制**到新槽目录，**不删不改原安装** —— 撤销只需删掉新槽目录；
2. 复制一份 `node` 运行时进新槽，保持「每槽自带 node」；
3. 分配独立数据目录（新槽内 `.dsh-home`）与独立端口，与原安装**不共享**；
4. 复制时**不跟随 junction**：指向旧槽的链接重新指向新槽，指向槽外的原样指回，目标丢失的如实记进"丢失清单"；
5. 写前备份 `config.json`。

> 顺序是先复制**用户数据**并逐文件核对，再复制几百 MB 程序。核对对不上就把目标目录改名 `-INCOMPLETE` 并中止 —— 宁可失败，不留"看着正常其实缺文件"的假槽。

**什么时候不该纳入**：纳入（无论原地接回还是复制）都**不修复任何东西**，只适合「**能正常跑**、只是没被管理器接管」的安装。

| 情况 | 该怎么做 |
|---|---|
| 原 dsh **跑不起来**（启动报错 / 依赖缺失 / node 版本不对） | 用「安装官方版 dsh」重装 |
| **半装/中断**（`npm install` 被 Ctrl-C 过、磁盘满过） | 同上 |
| 装在**很旧的版本**（0.1.2 之前） | 同上（入口结构不同，纳入后大概率起不来） |
| 想要**干净可控**的环境 | 同上（推荐） |

管理器会自动拦住明显残缺的安装：**两条路都走同一套体检**（版本号、`lib/bin.js`、`lib/` 非空、声明的依赖齐全），
缺任何一项都**直接拒绝**并说清缺什么。

被拒了想救一下？到「设置 → 维护 → **槽体检**」里选中那个槽点「修复…」——它只补 `node` 运行时和 `.dsh-home`/`.tmp` 空目录；
缺 `bin.js` / 依赖这类补不了的，会明确告诉你改用「安装官方版 dsh」重装。

> **拿不准就装新的。** 纳入不动你的原安装，代价只是一次复制的时间；重装一份是干净、已知可用的。

## 6. 减槽位：卸载 与 移出管理

「卸载 / 移出管理」窗口有**两个不同**的动作，选错代价差很远：

| | 卸载 | 移出管理 |
|---|---|---|
| 改什么 | 删整个槽目录 + 从 `config.json` 移除 | **只**从 `config.json` 移除 |
| 磁盘 | 先备份用户数据，再删程序产物 | **一个字节都不动** |
| 还能用吗 | 不能（除非从备份恢复） | **能** —— 双击槽里的 `dsh.bat` 照常启动 |
| 记在哪 | — | `config.json` 顶层 `detached`（**只存路径**，不存槽名/端口/旧配置） |

两者都是**一次一个**（单选）—— 一次删几百 MB，多选容易连带勾错。

### 6.1 卸载

流程：停进程 → 备份 → 删整个槽目录 → 从配置移除。

**备份到** `<安装根>\dsh备份\<槽名>-userdata-<时间戳>\`，里面是 `.dsh-home` 的全部内容（会话 / 设置 / 凭据 / 插件配置）+ 插件清单 `package.json` / `package-lock.json` + `_meta.json`（实装版本号与来源）。

**没有用户数据就不建备份目录**：`.dsh-home` 是空的（这个槽从没启动过）时，不会生成一个只有 `_meta.json` 的空备份，
日志里只记一行「没有用户数据（.dsh-home 为空），未生成备份（实装 x.y.z）」。

**边界**：

| 类别 | 卸载时 |
|---|---|
| 用户数据（`.dsh-home`） | **先备份、再删除**（槽目录整个删掉） |
| `config.json` | 改前自动备份为 `.bak-<时间戳>` |
| 程序产物（`node_modules` / `node` / 三件 bat / 槽根的 `package*.json`） | **删除** |
| 临时目录 | 在槽目录内（`.tmp`）→ **删除**；在槽外 → 保留 |
| 仓库源码 | **不动** |

> ⚠️ **你自己放进槽目录的东西（笔记、补丁、下载的文件）会跟着一起删，且不进备份。** 要留请先复制出去。
> 卸载确认框会把这类「不是 dsh 装出来的」条目**逐个点名列出来**，删完的提示里也会再说一遍。

**为什么把槽目录删干净**：残留目录会**一直占着这个编号**（`v4` 就永远轮不到新装的版本），
「dsh备份」和槽根也会越堆越乱。删完才 `rmdir` 槽根；万一删不掉（被占用），日志会如实说哪个目录没删干净。

**备份要么完整、要么中止**：备份后逐文件核对大小；对不上就把备份目录改名 `-INCOMPLETE` 并中止卸载。

### 6.2 移出管理

只改 `config.json`，磁盘不动。适合**把这批版本放出来自己跑**、再把管理器指到别的位置管另一批。

- **运行中的槽要先点「停止」**才允许移出 —— 移出后管理器不再跟踪它的进程，你就没有「停止」入口了；
- 移出的槽之后点「**扫描已装 dsh 并纳入**」就能重新发现并**原地接回**（不复制文件）：
  - **槽键从目录名推导**（`dshV3` → `v3`），不会因为旧键被占就顶个别的名字；
  - **端口从槽里的 bat 读**（那是实际启动用的值）；被别的槽占了会自动换一个空闲端口并重写三件 bat；
  - 接回前走和"复制纳入"**同一套体检**，缺 `bin.js` / 依赖会被拒 —— 想修去「设置 → 维护 → 槽体检」；
  - 接回后如果发现三件 bat 缺了，会自动重建一次（你手改过的 bat 不会被覆盖）；
- **全部移出后安装根解锁**（锁定条件就是"有没有在管的槽"），可以改到新位置再装新的。

> 为什么必须留档：换过安装根之后，旧位置的槽不在扫描范围内（只扫当前版本根和 npm 全局），没有这份记录就再也自动发现不了它们。
>
> 记录里存的是**绝对路径**而不是 `<base>` 占位符 —— 占位符会跟着新安装根漂移，反而指错地方。

### 6.3 命令行等价操作

```powershell
# 先看计划（零副作用，强烈建议先跑）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\uninstall.ps1 -Target v2 -DryRun

# 真删（会先备份）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\uninstall.ps1 -Target v2

# 卸掉全部槽
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\uninstall.ps1 -Target all
```

参数：`-Target`（槽键或 `all`，缺省交互选择）、`-DryRun`、`-Yes`、`-SkipBackup`、`-SkipGlobal`、`-Base`、`-ConfigPath`。

`uninstall-here.bat` 是同一套逻辑的交互式外壳。

## 7. 日志

所有动作写入**管理器目录下的 `dsh-manager.log`**（UTF-8）。排查顺序：

1. 看状态行（启动中 / 外部占用 / 已停止），末尾有没有 `⚠N`；
2. 翻 `dsh-manager.log` 最近的 `[v1]` / `[v2]` 行；
3. 对照 [`README.md`](../README.md) §七 的速查表。

| 前缀 | 记什么 |
|---|---|
| `[v1]` / `[v2]` … | 该槽的启动 / 停止 / 端口 / 环境变量 / 状态变化 |
| `[安装]` `[卸载]` `[纳入]` | 装槽、卸载、纳入（含备份路径） |
| `[体检]` | 体检结论（启动时浅查 + 点按钮深查） |
| **`[变更]`** | **插件安装 / 卸载 / 升级、`cordis.yml` 等配置被修改** —— 调试版本、开发插件时最有用的一类：`[变更] v2 插件 ~dsh-cost-meter 1.8.5→1.9.0（web）` |
| `[设置]` | 界面显示偏好、拖动排序、浏览器、安装根、主题 |
| `[环境]` `[清理]` `[检测]` | 环境体检、空壳目录、端口探测 |

> **`[变更]` 是怎么来的**：管理器启动时给每个槽拍一份指纹（各 profile 的插件名+版本、几个配置文件的内容哈希），之后每约 10 秒比一次，变了写一行。**只读** —— 不解析配置内容、不碰凭据（`.credentials.yaml` 连哈希都不算）、不看会话目录。所以「昨天还好好的，今天怎么不行了」翻日志就能看到是哪个插件什么时候被升了级。

**token 会自动打码，三层保证**：管理器自己的输出经统一脱敏；dsh 子进程写的 `dsh web: …?token=` 入口行被**就地等长覆盖**（保留前 4 位）；每次启动还会把历史日志再全量打码一遍。所以日志可以放心发给别人排查。需要完整入口 URL 时，用界面上的「复制入口 URL」。

## 8. 配置：`config.json`

> **最多 6 个版本槽**（`MAX_SLOTS`）。界面按「每槽两列」自适应排布，1~6 槽都能正常显示。
>
> 新增槽位不必手改文件：用「设置 → 版本管理」里的安装 / 纳入按钮即可（见 §5）。

管理器是**配置驱动**的，一切行为由管理器目录下的 `config.json` 决定（首次运行自动从 `config/config.example.json` 复制生成）。

### 占位符（写一次，到处可搬）

| 占位符 | 含义 |
|---|---|
| `<home>` | 当前用户主目录 |
| `<base>` | `install_base`，所有安装产物的根目录 |
| `<self>` | 管理器自身所在目录 |
| `<npm_global>` | 运行时 `npm root -g` 的结果（定位全局安装的 dsh） |

### 顶层字段

| 字段 | 说明 |
|---|---|
| `install_base` | 安装根目录。**有槽之后锁定** |
| `temp_root` | 已废弃（临时文件自动放各槽 `.tmp`）；保留仅为兼容旧配置 |
| `icon` | 窗口/快捷方式图标，相对管理器目录 |
| `versions` | 槽字典，键 `v1`…`v6`（上限 `MAX_SLOTS`） |
| `ui` | 可选：`max_visible` / `order` / `visible`。「设置」会写它，手写也行。**只影响渲染** |
| `detached` | 可选：已移出的槽**在哪**（只存绝对路径，不存槽名/端口）。**管理器自动写，别手改** |

### 每个槽的字段

| 字段 | 含义 |
|---|---|
| `label` | 槽目录名（如 `dshV1`），也是卡片上显示的名字 |
| `node_exe` | 用哪个 node 启动（通常是该槽自带的） |
| `bin_js` | dsh 入口 `lib/bin.js`。进程签名与槽根反推都靠它 |
| `dsh_home` | 数据目录（`DSH_HOME`）。**每槽必须独立** |
| `port` | 监听端口。**每槽必须独立** |
| `browser` | `default` / `chrome` / `edge` / `firefox` / 任意 exe 绝对路径 |
| `temp_dir` | 该槽的 `TEMP`/`TMP`，缺省 `<槽目录>/.tmp`。**别手改** |
| `extra_args` | 传给 `bin.js` 的参数数组，如 `["web","--host","127.0.0.1","--port","4080","--no-open"]` |

### 手改配置的三条硬规矩

1. **写文件必须无 BOM**。Python 的 `json.load` 遇 BOM 会崩，而管理器会把崩掉的配置判成坏配置。
   - 别用 PowerShell 5.1 的 `Set-Content -Encoding utf8`（它写 BOM）；
   - 用编辑器的「UTF-8 无 BOM」，或让管理器自己改。
2. **改 `port` 要同步改 `extra_args` 里的 `--port`**，否则预检与实起不一致；还要点一次「生成启动/kill/CLI bat」。
3. **改完重启管理器** —— 启动时只读一次配置。（管理器自己改配置时会**原地刷新**，不需要你重启；
   只有手改文件、或换了代码才要重启。）

管理器写配置一律**原子写**（先写 `config.json.tmp-<pid>` 再 `os.replace`），改前自动备份 `config.json.bak-<时间戳>`；解析失败会备份成 `.bad-<时间戳>` 再从模板重建，并**弹框告诉你**（不静默覆盖）。

**想换浏览器 / 端口 / 目录，多数情况不用改文件**：浏览器在「设置」里选，安装根在「设置 → 目录」里改，新槽由「安装官方版 dsh」自动分配端口。

## 9. 安全与隐私

- **不收集、不上传、不遥测**：全部代码在你本机执行，没有任何数据离开你的电脑。
- **需要联网的只有两处**，都是你主动触发的：拉取版本列表、安装 dsh（都走 npm registry，失败回退 `registry.npmmirror.com`，仅本次命令生效）。
- **启动、停止、杀进程、端口检测、日志、生成 bat、扫描已有安装** —— 这些日常操作**完全离线**。
- **用户数据只在你卸载时删，且删前一定先备份**：卸载会先把 `.dsh-home` 复制到 `dsh备份\` 并逐文件核对，
   对不上就中止、一个文件都不删；核对通过才随槽目录一起删除。移出管理则一个字节都不动。
- **杀进程只杀认得出的 dsh**：签名 = 该槽 `bin.js` 绝对路径，外加端口兜底；端口被非 dsh 程序占用时**拒绝杀**。
- **不写全局 `PATH`、不改注册表**，只动与 dsh 相关的最小范围。
- **日志里有什么**：`?token=...` 已等长打码（三层保护），但**本机路径和用户名照常保留**
  —— 排查时需要它。对外发日志前，建议把 `C://Users//<你的用户名>` 这类替换掉。
- **`dsh备份\` 里有明文凭据**：它是 `.dsh-home` 的完整副本，含 `.credentials.yaml`（登录凭据）。
  别把这个目录同步到网盘、发给别人或提交进仓库；确认不再需要后再删。
- **剪贴板**：卡片上的「复制入口 URL」会把带 token 的地址放进剪贴板，本机任何程序都能读。
  粘完可以随手复制点无关内容覆盖掉。
- **`config.json` 含本机绝对路径**（带用户名），贴给别人看配置前注意。
- 全部代码开源（MIT），你可以审计 `dsh_*.py` 与 `scripts/` 确认上述承诺。

## 10. 常见问题

| 现象 | 处理 |
|---|---|
| 双击 `start-manager.bat` 没反应 | 用 `start-manager-debug.bat` 看 traceback；或看 `dsh-manager.log`。多半是 Python 缺 tkinter |
| 某个槽「启动」后秒退 | 点「槽体检」；日志里 `Cannot find module` 说明依赖缺，卸载重装 |
| 浏览器 401 | 用「打开浏览器」按钮开一次（种 30 天 cookie）；或「复制入口 URL」粘到别的浏览器 |
| 想用 Firefox / 便携浏览器 | 标题栏「设置」→「选中的槽用哪个浏览器打开」→ 选 Firefox 或「选择其他程序…」 |
| 端口被占（EADDRINUSE） | 先点卡片「停止」或标题栏「全部停止」；或 `netstat -ano \| findstr :<端口>` 找 PID 后结束 |
| 想换某个槽的 dsh 版本 | 「卸载 / 移出管理」卸掉旧槽（会备份数据）→ 再「安装官方版 dsh」装新版本 |
| 想把版本放出来自己跑、换个位置再管一批 | 「移出管理」逐个放走 → 全部放走后安装根解锁 → 改位置 → 装新的。想回头点「扫描已装 dsh 并纳入」，勾选后**原地接回**（不复制） |
| C 盘满了 / 想把已装版本换到别的盘 | 「设置 → 目录 → 移动安装根目录…」整体搬过去，**不用卸载**；搬前会先算空间并要求所有槽先停止 |
| 改过临时目录，但 `dsh.bat` 里还是旧路径 | 点「生成启动/kill/CLI bat」重建 |
| 临时目录根下的空文件夹删了又出现 | 那是**回归测试**造的（`dshV9` 只存在于测试脚本里），产品行为不会往那里写。见 [`常见问题.md`](常见问题.md) Q6c |
| 想彻底清掉 | 卸载全部槽后手动删仓库文件夹即可（卸载不会删仓库） |

更多见 [`常见问题.md`](常见问题.md)。
