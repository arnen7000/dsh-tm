## 1. 先搞清两件事：dsh 与本管理器

| | 是什么 | 文档在哪 |
|---|---|---|
| **dsh**（DeepSeek Harness） | DeepSeek 官方的 Agent 运行时。你在网页对话框里给它派活，它写代码、跑命令、查资料 | 本文件 + [§3 官方原文](#3-官方原文逐字快照可选) |
| **本管理器** | 本仓库的开源工具。让你在同一台电脑上**并行跑多个互相隔离的 dsh 版本**，各有各的进程 / 端口 / 数据目录 | [`dsh管理器功能说明书.md`](dsh管理器功能说明书.md) |

两者是**上下游**关系，不是同一件事：本管理器负责"装与管"，dsh 负责"干活"。

## 2. 快速上手 dsh 本体

```bash
# 方式一：不装，临时跑一次（新手最快）
npx -y @deepseek-ai/dsh web

# 方式二：全局安装（推荐日常用）
npm install -g @deepseek-ai/dsh
dsh web
```

前置要求：**Node.js ≥ 22.19**（`node --version` 检查）。低于此版本会直接报错。

启动后浏览器访问 `http://127.0.0.1:3080`。

日常用法速查：

| 你想… | 怎么做 |
|---|---|
| 打开网页版 | `dsh web` |
| 换模型 / 思考强度 | 网页设置里改；或编辑 `%USERPROFILE%\.dsh\settings.yaml` 的 `agent-default-model` |
| 一次问答，不要界面 | `dsh --profile headless "帮我总结这个文档"` |
| 装个插件 | 见 [§3 官方原文](#3-官方原文逐字快照可选) 的插件章节 |
| 看当前生效配置 | `dsh --dump-config` |

数据位置：**所有个人数据（会话、配置、插件）都在 `%USERPROFILE%\.dsh`**（即 `$DSH_HOME`）。删掉 dsh 程序不影响这些数据；想备份/迁移，拷这个目录即可。

> 💡 Windows 用户注意：PowerShell 里敲 `dsh` 若提示脚本被禁用，改用 **`dsh.cmd`** 即可。
> 💡 想同时跑多个版本、或不想让 dsh 占用默认数据目录，请用本管理器——它为每个版本注入独立的 `DSH_HOME`。

## 3. 官方原文（逐字快照，可选）

> **本仓库暂未收录官方手册快照。**
>
> 早期版本曾附带一份 `官方手册-0.1.5-rc.2/`（从 dsh 源码 tag 逐字抽取，结构与官方仓库一致），
> 但它体积大、更新成本高，且很快就与实际版本脱节，因此**已从仓库移除**。
>
> 需要官方原文时，请直接取用上游渠道：
>
> | 去哪 | 地址 |
> |---|---|
> | 官方文档站（推荐，含多版本） | <https://deepseek-harness.github.io/deepseek-harness/> |
> | 官方仓库中文手册源码 | <https://github.com/deepseek-ai/DeepSeek-Harness> |
> | 本机已安装版本的随包文档 | `<你的版本目录>\node_modules\@deepseek-ai\dsh\docs\` |

### 为什么不再自带快照

1. **会过期**：快照绑定某个 tag（如 0.1.5-rc.2），而管理器支持多版本并存，读者手上的版本未必是它。
2. **体量大**：官方 `docs/` 全量抽取后近万行，多数是本项目用不到的开发者向大部头（catalog / graph 类文件）。
3. **易误导**：过期的"官方文档"比没有文档更糟——读者会照着不存在的接口写代码。

如果你确实需要在仓库内固定某版手册，做法是从该版本的源码 tag 里原样抽取 `docs/`（不改结构、不改链接），并按版本号放进一个独立目录。建议放在独立仓库或 release 附件里，不要进主仓库。
