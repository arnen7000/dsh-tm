# DSH-TM v0.1.13 验收记录

2026-11-25 在 Apple Silicon、macOS 27.0.1、Python 3.12.15 和 Tk 9 上完成本地复验。测试使用隔离 HOME、配置、缓存和槽目录。端口 `4080`、`5080` 在测试开始时空闲，结束时都已释放。

| 用户视角 | 实际运行与结果 | 证据边界 |
| --- | --- | --- |
| 第一次使用 | 本地重建 arm64 ZIP 校验通过，解包 App 实测零槽引导、位置确认和版本选择。原生 Tk 用真实 npm 装入 `0.2.2-rc.1`，前台、后台和恢复进度均通过，新增卡片早于成功通知。 | 成品桌面控制在版本选择后超时。后续由原生 Tk 调用生产控件，消息框回答使用测试替身。 |
| 同机使用两个版本 | 实际运行 `rc.1` 时，通过设置安装 `rc.5`。旧槽进程和夹具数据保留，启停控件仍可用。安装后两槽的 Node、数据目录和端口都不同，两槽均验证未认证 401 和认证后 200。 | 原生 Tk 连真实 npm 和实际 dsh。浏览器视觉流程未覆盖。 |
| 遇到旧 npm 缓存 | 包内真实 npm 对隔离的本机 registry 先缓存旧依赖清单。原缓存路径复现 `ETARGET`。新路径在线核对一次后安装到正确版本。确实缺失的版本仍报告失败。 | registry 和测试包为夹具，npm 进程、缓存、请求和安装文件为真实操作。真实 dsh 下载另见双槽与打包测试。 |
| 安全卸载 | 首次取消后配置字节不变，目标仍运行。确认后目标停止、端口释放、备份内容逐字节一致，另一槽持续运行。卸掉最后一槽后设置和安装位置入口解锁。 | 原生 Tk 运行生产逻辑，交互回答使用替身。成品上的卸载消息框和通知层级未覆盖。 |
| CLI 与发布产物 | 独立对 arm64 包跑 `rc.1` 与 `rc.5` 的真实 npm 生命周期。HTTP 认证、打包 CLI 启停、运行中槽的备份卸载、配置扩展字段保留通过。App ZIP 核对了签名、架构、SHA-256 和随包文档。 | 安装由测试脚本调用共享安装逻辑，启停使用打包 CLI。 |

原生 Tk 测试使用包内 Node 和 npm 镜像。两个版本从完成进度切换到卡片和结果可用分别约 13.6 秒和 18.1 秒。两组打包生命周期测试分别约 38.5 秒和 31.9 秒，第一组包含等待 App 启动快照。耗时来自该主机和隔离缓存，仅供复验对照。

独立运行源码自检时发现兼容性检查误将 npm 错误正则当成类型注解。修复后，同一零槽环境退出码为 0。回归确认实际的 `str | None` 类型注解仍会报告需 Python 3.10。

macOS 13.5、实体 Intel Mac、实际双屏、普通 Windows 10 / 11 桌面环境没有本次实机证据。GitHub Release 应以本版本对应运行的结果单列 macOS 15 双架构、Windows 托管 runner 与各自执行的步骤。[历史 v0.1.12 验收](test-coverage-v0.1.12.md)
